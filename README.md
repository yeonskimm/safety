# 오늘의안전 (Today's Safety)

[![tests](https://github.com/yeonskimm/safety/actions/workflows/test.yml/badge.svg)](https://github.com/yeonskimm/safety/actions/workflows/test.yml)

안전관리 인력이 부족한 **소규모·취약 사업장**의 현장 작업자가, 설치 없이 브라우저만으로 작업 전 안전점검을 마치고 AI 상담까지 받을 수 있는 PWA입니다.

- 서비스: <https://yeonskimm.github.io/safety/>
- 현재 버전: **v96**
- 개발·운영: 대구지방고용노동청 광역산재예방감독과

---

## 1. 왜 만들었나

소규모 사업장은 전담 안전관리 인력을 두기 어려운 경우가 많아, 현장 작업자가 "오늘 이 작업에서 무엇을 확인해야 하는지"를 스스로 판단해야 합니다. 기존 안전점검표는 종이 기반이고 업종·작업 구분이 없어 현장에서 잘 쓰이지 않습니다.

이 앱은 **업종 → 작업 → 체크리스트**의 3단계만으로 그날 그 작업에 맞는 점검 항목을 제시하고, 결과를 이미지 보고서로 남깁니다.

## 2. 주요 기능

| 기능 | 설명 |
|---|---|
| 맞춤 체크리스트 | 업종·작업 선택 시 해당 작업의 점검 항목 자동 구성. 중대재해 직결 항목은 별도 표시 |
| 비정형 작업 LOTO | 수리·청소 등 비정형 작업에 전원 차단·잠금·표지 절차 안내 |
| AI 안전 리포트 | 점검 결과를 바탕으로 위험 진단 리포트 생성, 이미지 저장·공유 |
| AI 안전상담 | 산업안전보건법령 기반 질의응답. 실제 주입된 조문을 근거 칩으로 표시 |
| 한/영 이중언어 | 외국인 근로자를 위한 전체 화면 영문 전환 |
| 체감온도·폭염 단계 | 기상청 공식 산식 기반 체감온도 계산 및 단계별 조치 안내 |
| 점검 이력 | 최근 200건 로컬 보관, 월별 조회 |
| 오프라인 동작 | Service Worker 캐시로 네트워크 없이도 체크리스트 이용 가능 |

## 3. 아키텍처

```
[브라우저 PWA]                  [Cloudflare Worker]           [외부 API]
 index.html          ─ HTTPS ─▶  safety-ai-proxy  ────────▶  Groq (gpt-oss-120b)
 service-worker.js                · 법령 RAG 검색              └ 실패 시 Gemini 폴백
 manifest.json                    · 프롬프트 구성             Open-Meteo / wttr.in
 (GitHub Pages)                   · 답변 조문 검증            BigDataCloud
                                  · 이용통계 (KV)
        law_kb.json ────────────▶
        (법령 1,230조문)
```

- **API 키는 앱에 존재하지 않습니다.** 모든 외부 호출은 Worker를 경유합니다.
- Worker는 `https://yeonskimm.github.io` 출처만 허용합니다(CORS 화이트리스트).
- 관리자 인증은 서버에서 PIN을 검증하고 세션 토큰을 발급합니다(v94부터). 앱 코드에 PIN이 없습니다.
- AI 시스템 프롬프트는 Worker에 고정되어 있어, 앱 밖에서 요청을 흉내 내도 역할을 바꿀 수 없습니다(v96부터). IP당 요청 한도(분당 15·시간당 120)와 답변 길이 상한을 서버에서 적용합니다.

## 4. 법령 검색 (RAG)

AI가 법 조항을 지어내지 않도록 3단계로 방어합니다.

1. **검색** — 질문에서 키워드·동의어를 뽑아 `law_kb.json`에서 관련 조문을 항(項) 단위로 추출
2. **주입** — 추출된 조문 원문만 프롬프트에 넣고, 적용 요건·단서(`lawProvisos`)를 별도로 명시
3. **검증** — 생성된 답변에 주입하지 않은 조문번호가 있으면 표기를 제거하고 확인 안내를 붙임

화면의 `📖 법령 근거` 칩은 **AI가 쓴 문장이 아니라 검색엔진이 실제로 주입한 조문 목록**입니다.

### 법령 DB

| 법령 | 적용 원문 (시행일) | 조문 수 |
|---|---|---|
| 산업안전보건법 | 법률 제21374호 (2026.6.1) | 184 |
| 산업안전보건법 시행령 | 대통령령 제36540호 (2026.8.1) | 125 |
| 산업안전보건법 시행규칙 | 고용노동부령 제477호 (2026.8.1) | 252 |
| 산업안전보건기준에 관한 규칙 | 고용노동부령 제454호 (2025.12.1) | 669 |
| **합계** | | **1,230** (+ 별표 13종 350청크) |

- 조문: 국가법령정보센터(법제처 Open API) 원문을 [legalize-kr](https://github.com/legalize-kr/legalize-kr) Markdown 미러에서 받아 `tools/build_kb_from_md.py`로 생성합니다(v96).
- 기준: **빌드일 현재 시행 중인 조문**. 공포됐으나 시행 전인 개정은 넣지 않습니다.
  - 🔔 다음 갱신: **2026.12.8** — 법률 제21534호(근로감독관 → 노동감독관 명칭 변경 등, 제6·23·155·156·157·175조) 시행일
- 별표: 원문 미러에 없어 HWPX 원본에서 추출한 청크를 유지합니다.
- 선 문자 표는 `〔표〕 칸 | 칸 / 다음 행 〔표 끝〕` 한 줄로 펼쳐 넣습니다(산안규칙 제321·430·454·500·530조).
- 파싱 오류가 확인된 조문은 `bad` 플래그로 검색에서 제외할 수 있습니다(현재 0개).

> ⚠️ 이 앱의 안내는 참고용입니다. 법적 효력이 있는 해석은 국가법령정보센터(law.go.kr) 또는 관할 고용노동청에서 확인하십시오.

## 5. 파일 구조

```
index.html          앱 본체 (단일 파일 — HTML/CSS/JS 일체)
service-worker.js   오프라인 캐시 (Stale-While-Revalidate)
manifest.json       PWA 매니페스트
law_kb.json         법령 검색 DB
worker.js           Cloudflare Worker (AI 프록시 · RAG · 통계 · 관리자)
tools/              법령 DB 빌드 도구
  hwpx_extract.py   별표 HWPX -> 텍스트
  build_annex.py    별표 청크 생성
  build_kb.py       law_kb.json 빌드
  validate_kb.py    빌드 결과 검증 (본문 잘림 검사 포함)
  build_kb_from_md.py  법제처 원문(Markdown)으로 조문 전체 재생성 — 법령 개정 시 사용
  restore_articles.py  특정 조문만 원문으로 교체
tests/
  run_all.sh        전체 검증 일괄 실행
  test_retrieve.js  법령 검색 회귀 테스트
  test_verify.js    답변 조문 검증 로직 테스트
  test_admin.js     관리자 인증 단위 테스트
  test_proxy.mjs    AI 프록시 보호 통합 테스트 (프롬프트 고정·IP 한도·중대재해처벌법 가드)
  test_ui.py        렌더링 테스트 (Playwright)
  test_privacy.py   개인정보 안내 동작 테스트 (Playwright)
```

법령이 개정되면 `build_kb_from_md.py`(사용법은 파일 머리말) → `validate_kb.py` → `tests/run_all.sh` 순으로 실행하고, `worker.js`의 `LAW_KB_VER`와 KB `meta.빌드버전`을 함께 올립니다.
별표를 추가할 때는 `hwpx_extract.py` → `build_annex.py` → `build_kb.py` → `validate_kb.py` 순으로 실행합니다.

## 6. 검증

모든 릴리스 전에 저장소 루트에서 실행합니다.

```bash
bash tests/run_all.sh    # 실패 시 종료코드 1
```

`main`에 push할 때마다 GitHub Actions가 같은 검증을 자동으로 실행합니다 (`.github/workflows/test.yml`).

검사 항목:

- JS 문법 (`node --check`)
- 법령 KB 구조 검증 — 오분할·부칙 혼입·**본문 잘림**·중복 조번호
- 법령 검색 회귀 테스트 (58문항) / 답변 조문번호 검증 (19항목)
- 관리자 인증 / AI 프록시 보호 통합 테스트
- `APP_VERSION`(index.html) ↔ `CACHE_NAME`(service-worker.js) 버전 동기화
- `LAW_KB_VER`(worker.js) ↔ KB 빌드버전 동기화 — KB를 고치고 캐시키를 안 올리면 Worker가 옛 KB를 계속 씀
- 평문 비밀값 잔존 검사
- Playwright 렌더링·개인정보 안내 테스트

## 7. 개인정보 처리

- 점검 이력·설정은 **이용자 기기(localStorage)에만** 저장되며 서버로 전송되지 않습니다.
- 서버(KV)에 저장되는 것은 익명 이용통계와, 이용자가 직접 남긴 의견·연락처(180일 후 자동 삭제)뿐입니다.
- 관리자 화면의 연락처는 기본 마스킹 표시되며, 회신이 필요할 때만 탭하여 전체를 확인합니다.
- 정확한 위·경도 좌표는 저장하지 않습니다. 날씨 조회에만 사용하며, 익명 이용통계를 위해 **시·군·구 수준의 지역값과 기기 종류(iOS/Android)만** 집계합니다.
- 방문 분석을 위해 Google Analytics를 사용합니다.
- 의견 보내기에서 연락처를 적을 때만 수집·이용 동의를 받으며, 창 안의 「개인정보 처리 안내 보기」에서 위 내용을 확인할 수 있습니다(v96).
- AI 입력 내용은 답변 생성을 위해 외부 AI 서비스로 전송됩니다. 입력창 위에 개인정보 입력 자제 안내를 표시하고, 서버 로그에 질문 원문을 남기지 않습니다(v96).

## 8. 기술 스택

- 프론트엔드: 단일 HTML 파일 (빌드 도구·프레임워크 없음)
- 호스팅: GitHub Pages
- 백엔드: Cloudflare Workers + Workers KV
- AI: Groq `openai/gpt-oss-120b` (폴백: Google Gemini)
- 날씨: Open-Meteo (폴백: wttr.in) / 위치: BigDataCloud

프레임워크를 쓰지 않은 이유는 현장 단말의 네트워크가 불안정한 경우가 많아, **첫 로딩에 추가 요청이 발생하지 않는 구조**가 필요했기 때문입니다.

  - 산안규칙 표 복구(제어풍속·접근 한계거리·필요환기량 식 등), 제2조(정의) 격리 해제 → 격리 조문 0개
  - 조문 끝에 붙어 있던 다음 장·절 제목과 삭제 조문 표기 제거
- **벌칙 조문 복구** — 법 제167·168·169·174·175조 본문이 추출 중 잘려 있어, "안전조치 위반하면 처벌?"에 제170~172조가 주입되던 문제 해결. 법 제1조(목적) 격리 해제
  - 원문: 법제처 Open API 기반 Markdown 미러(legalize-kr), 법률 제21374호. 법 184개 조문 전체를 원문과 대조해 불일치가 이 6개뿐임을 확인
- 직결 사전 보강 — 사망 시 처벌 → 제167조·제173조(양벌), 위반 처벌 → 제168조
- **중대재해처벌법 질문 가드** — DB에 없는 법이라 산안법 조문을 주입하지 않고, 단정 금지·law.go.kr 확인 안내만 전달
- **AI 프록시 보호** — 시스템 프롬프트 서버 고정, IP당 요청 한도, 답변 길이·온도 상한, 로그에서 질문 원문 제거
- **개인정보 안내** — 의견 보내기 연락처 수집·이용 동의, 처리 안내(접힘), AI 입력창 안내 한 줄
- 법령 근거 칩 색상 대비 개선(1.4 → 8.9) — 밝은 화면에서 거의 안 보이던 문제
- 작은 화면에서 의견 보내기 창이 화면을 넘어 보내기 버튼이 잘리던 문제 해결(창 내부 스크롤)
- 검증 추가: KB 본문 잘림 검사, KB 캐시키 동기화, 프록시 통합 테스트, 개인정보 안내 테스트
